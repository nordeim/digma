# AGENTS.md — Digma

Single Next.js 16 app (App Router) that clones the reference Digma design workspace: five page routes (`/`, `/Dashboard`, `/login`, `/Recent`, `/Teams`, `/Editor?projectId=` — capitalized for reference parity, root `/` and lowercase `/login` excepted; legacy lowercase URLs 307 via `src/middleware.ts`), a DOM-element canvas editor with an AI assistant, Prisma/SQLite persistence, and cookie-session auth. Clone remote: `https://github.com/nordeim/digma.git`; pushes go to the SSH remote via `docs/ssh_git_wrapper_v3.py`.

## Commands

| Task | Command |
|------|---------|
| Install | `bun install` (or `npm install`) |
| Dev server (port 3000) | `bun run dev` |
| Production build | `bun run build` |
| Production server | `bun run start` |
| Lint | `bun run lint` |
| Type check | `bun run typecheck` |
| Unit tests (92 checks) | `bun run test` |
| Browser E2E (107 checks; needs a build) | `bun run test:e2e` |
| Prisma client after schema change | `bunx prisma generate` |
| Recreate DB from schema | `bun run db:push` |
| Seed demo workspace | `bun run db:seed` |
| End-to-end smoke suite | `./scripts/smoke-test.sh` (needs `bun run build` first) |

**Gate order before every push:** `bun run lint` → `bun run typecheck` → `bun run test` (92) → `bun run build` → `./scripts/smoke-test.sh` (28 checks) → `bun run test:e2e` (107 Playwright checks — boots the standalone server on :3100 against its own `db/e2e.db` (the global setup seeds then BACKDATES one project's `lastOpenedAt` 11 days so the access-based stats pin has its discriminating datum), with `DIGMA_DISABLE_AI_LLM=1` so the deterministic fallback answers every AI assertion). There is no hosted CI; the local gate is the only gate. `next.config.ts` sets `ignoreBuildErrors` — the explicit `typecheck` step is what catches type errors; never skip it. `bun.lock` is the only lockfile (npm users regenerate their own). **Run the smoke suite with the dev server stopped** — it boots its own standalone server on :3000 and only kills `standalone/server.js`/`next start`, so a lingering `next dev` silently steals the port (symptom: rate-limit cascading failures).

First-run setup: `bun install && cp .env.example .env && bun run db:push && bun run db:seed && bun run dev`. Demo login: `demo@digma.app` / `Digma1234!`.

**Environment trap:** a parent workspace `.env` (or an exported shell `DATABASE_URL`) silently overrides the repo's relative SQLite URL with an absolute path to a different (or missing) file — symptom: `Error code 14: Unable to open the database file`. The `[db] DATABASE_URL -> …` startup log line is the diagnostic; unset the var or delete the stale parent `.env`. **In an agent's tool-call shell the exported var RE-INHERITS from the parent environment on EVERY invocation — an `unset` in a previous command does not persist; unset and run in the SAME command** (`unset DATABASE_URL && bun run db:seed`). The app itself is immune (db-path.ts normalizes); only bare-`PrismaClient` scripts (prisma/seed.ts) are exposed.

## Architecture facts you would otherwise guess wrong

- **Every page is session-gated server-side.** `page.tsx` files call `getSessionUser()` and `redirect("/login?from_url=…")` — the client views never gate themselves. All API reads/mutations are session-gated too (`requireSession()` first line, 401 envelope otherwise). Only `/api/health` and `/api/auth/*` are public.
- **The editor state lives in ONE Zustand store** (`src/components/editor/editor-store.ts`) — elements, selection, tool, zoom/pan, save flag, undo/redo snapshots. Views and panels read the store and call actions; nothing else owns canvas state. Mutations flip `saveState` to `unsaved`; the autosave effect (in `editor-view.tsx`) debounces 800ms and `PUT`s the FULL element list to `/api/projects/[id]/elements`, then remaps ids from the response so selection survives the replace. **Unknown/missing `?projectId` NEVER dead-ends**: the editor opens in "Untitled" mode (`UNTITLED_PROJECT`, ADR-009) and the first autosave `POST`s `/api/projects`, binds the new id (`store.attachProject`), and adopts it via `history.replaceState` — the reference app instead silently saves into the most-recent project (a data bug this clone deliberately does not copy; pinned by `tests/e2e/untitled-editor.spec.ts`).
- **The bottom-left editor chips are INDEPENDENT panel toggles, not tabs** (reference parity, ADR-010): a floating bar (`absolute bottom-4 left-4`) of `Layers | Components | Properties` chips, each flipping its own panel's visibility — Layers (left w-60) and Components (a second w-60 column) can both be open; Properties toggles the right w-72 panel. Default ON/OFF/ON. Chip state: `bg-blue-600 text-white` = on, panel-dark = off. **The bar renders only where its panels can: `hidden md:flex`, and the Properties chip additionally `hidden lg:inline-block`** (the panels are `md:flex`/`lg:flex`) — chips that toggle invisible state are dead controls that lie via `aria-pressed`. `tests/e2e/editor-panels.spec.ts` pins it. The panels stay hidden below `md`/`lg` (the mobile editor keeps a full-width canvas — a deliberate improvement over the reference's squeezed columns).

## Conventions that differ from defaults

- **Editor colors are `editor-*` Tailwind utilities** (`--color-editor-bg/panel/border/text` in `@theme`) — use them for the dark chrome instead of re-typing `#0d1117` hex.
- **Icons render at lucide default stroke** everywhere except editor panel headers where a softer look is used via smaller sizes. Toolbar buttons carry `title="{Tool} ({shortcut})"`.
- **Element types:** `rectangle | ellipse | line | text | frame | image | path` — `image`/`path` are in the vocabulary but currently minimal (pen/image tools select but never draw — measured parity: the reference's own Image tool is a dead no-op, RA-14). **The line's measured contract (session 29):** SVG diagonal stroke, transparent fill, stroke #FFFFFF, strokeWidth 2 — never a box border. **The text's measured contract:** content "Type here...", fontSize 16, fontFamily "Inter" (7-option enum) rendered as `"Inter, sans-serif"` for the default (session 33, RA-30 — only the default carries the fallback chain; chosen families render verbatim), textAlign rendered on the canvas. **The frame's measured contract (session 31, RA-13): a LABELED CONTAINER** — `defaultElementFor("frame")` returns `fill: null, stroke: "#555555", strokeWidth: 1, radius: 0` (the 1px border comes from the standard stroke mechanism, rendered by the shared style chain at the canvas, thumbnail, and present sites), plus an ALWAYS-ON name-label chip: `-top-5 left-0 text-xs text-gray-300 bg-[#161b22] px-1.5 py-0.5 pointer-events-none whitespace-nowrap` carrying `transform: scale(1/zoom); transform-origin: left top` — the label's text stays a CONSTANT screen size at any zoom (the zoom reaches `CanvasElement` as a frame-only prop so other types stay memoized). The thumbnail renders the frame border WITHOUT the label (RA-19).
- **Deletes confirm inline or via dialogs local to the card** (team cards swap Delete → "Yes, Delete / Cancel"); project deletes go through the ellipsis menu into a card-local "Delete project?" dialog with an explicit "Yes, Delete / Cancel" confirm (session 31 — the reference's own guard is a native `window.confirm`, RA-16). **Card-local dialogs (rename + delete) render through React PORTALS — and React propagates portal events through the REACT tree, so they wrap in a `stopPropagation` div (click AND keydown) or their Cancel clicks bubble to the card's `openProject` and silently navigate to the editor (the S31-3 lesson).** Never reintroduce `AlertDialog` global confirms.
- **ESLint ignores `skills/`** (the operator's skill catalog, not app code) plus build output dirs — don't remove those ignores.
- **`use client` is explicit** on every interactive component; pages stay server components.
