# AGENTS.md — Digma

Single Next.js 16 app (App Router) that clones the reference Digma design workspace: five page routes (`/`, `/Dashboard`, `/login`, `/Recent`, `/Teams`, `/Editor?projectId=` — capitalized for reference parity, root `/` and lowercase `/login` excepted; legacy lowercase URLs 307 via `src/proxy.ts` — the Next 16.3 `proxy` convention, renamed from `middleware.ts` in session 12), a DOM-element canvas editor with an AI assistant, Prisma/SQLite persistence, and cookie-session auth. Clone remote: `https://github.com/nordeim/digma.git`; pushes go to the SSH remote via `docs/ssh_git_wrapper_v3.py`.

## Commands

| Task | Command |
|------|---------|
| Install | `bun install` (or `npm install`) |
| Dev server (port 3000) | `bun run dev` |
| Production build | `bun run build` |
| Production server | `bun run start` |
| Lint | `bun run lint` |
| Type check | `bun run typecheck` |
| Unit tests (625 checks) | `bun run test` |
| Browser E2E (236 checks; needs a build) | `bun run test:e2e` |
| Prisma client after schema change | `bunx prisma generate` |
| Recreate DB from schema | `bun run db:push` |
| Seed demo workspace | `bun run db:seed` |
| End-to-end smoke suite | `./scripts/smoke-test.sh` (needs `bun run build` first) |

**Gate order before every push:** `bun run lint` → `bun run typecheck` → `bun run test` (625) → `bun run build` → `./scripts/smoke-test.sh` (58 checks — **run it as `unset DATABASE_URL && ./scripts/smoke-test.sh` in the SAME command**: the smoke server inherits the parent shell's exported URL otherwise and opens an EMPTY database — the User table missing, every auth route 500s) → `bun run test:e2e` (236 Playwright checks — boots the standalone server on :3100 against its own `db/e2e.db` (the global setup seeds then BACKDATES one project's `lastOpenedAt` 11 days so the access-based stats pin has its discriminating datum), with `DIGMA_DISABLE_AI_LLM=1` so the deterministic fallback answers every AI assertion). There is no hosted CI; the local gate is the only gate. `next.config.ts` sets `ignoreBuildErrors` — the explicit `typecheck` step is what catches type errors; never skip it. `bun.lock` is the only lockfile (npm users regenerate their own). **Run the smoke suite with the dev server stopped** — it boots its own standalone server on :3000 and only kills `standalone/server.js`/`next start`, so a lingering `next dev` silently steals the port (symptom: rate-limit cascading failures). **After a prisma schema change, RESTART the dev server** — a running `next dev` holds the client generated at boot and every element write 500s with `PrismaClientValidationError` until restarted. **The e2e auth-call budget: the rate limiter (10/IP/15min) covers register/verify-otp/resend-otp/forgot-password/reset-password too — `auth.spec.ts` keeps its shared-bucket TOTAL auth calls at 9 of 10 (the Resend round-trip lives in the smoke suite's own server/bucket; session 45's exhaustion section (smoke) and weak-password pin (e2e) each declare a DEDICATED `X-Forwarded-For` bucket, and session 46's reset spec declares its own — the limiter keys on XFF); add auth calls to the e2e suite with extreme care.

First-run setup: `bun install && cp .env.example .env && bun run db:push && bun run db:seed && bun run dev`. Demo login: `demo@digma.app` / `Digma1234!`.

**Environment trap:** a parent workspace `.env` (or an exported shell `DATABASE_URL`) silently overrides the repo's relative SQLite URL with an absolute path to a different (or missing) file — symptom: `Error code 14: Unable to open the database file`, or (session 43's coarser variant) the SMOKE server silently creating an EMPTY database and 500ing every auth route (`The table main.User does not exist`). The `[db] DATABASE_URL -> …` startup log line is the diagnostic; unset the var or delete the stale parent `.env`. **In an agent's tool-call shell the exported var RE-INHERITS from the parent environment on EVERY invocation — an `unset` in a previous command does not persist; unset and run in the SAME command** (`unset DATABASE_URL && bun run db:seed`, `unset DATABASE_URL && ./scripts/smoke-test.sh`). The app itself is immune (db-path.ts normalizes); bare-`PrismaClient` scripts (prisma/seed.ts), the smoke boot, AND THE DEV SERVER are exposed — `bun run dev` inherits the exported var the same way (session 47's restart opened a MISSING out-of-repo database and every API route 500'd until the `unset DATABASE_URL && bun run dev` restart), so ALWAYS read the `[db]` anchor line after any dev-server start.

## Architecture facts you would otherwise guess wrong

- **Every page is session-gated server-side.** `page.tsx` files call `getSessionUser()` and `redirect("/login?from_url=…")` — the client views never gate themselves. All API reads/mutations are session-gated too (`requireSession()` first line, 401 envelope otherwise). Only `/api/health` and `/api/auth/*` are public.
- **The editor state lives in ONE Zustand store** (`src/components/editor/editor-store.ts`) — elements, selection, tool, zoom/pan, save flag, undo/redo snapshots. Views and panels read the store and call actions; nothing else owns canvas state. Mutations flip `saveState` to `unsaved`; the autosave effect (in `editor-view.tsx`) debounces 800ms and `PUT`s the FULL element list to `/api/projects/[id]/elements`, then remaps ids from the response so selection survives the replace. **Unknown/missing `?projectId` NEVER dead-ends**: the editor opens in "Untitled" mode (`UNTITLED_PROJECT`, ADR-009) and the first autosave `POST`s `/api/projects`, binds the new id (`store.attachProject`), and adopts it via `history.replaceState` — the reference app instead silently saves into the most-recent project (a data bug this clone deliberately does not copy; pinned by `tests/e2e/untitled-editor.spec.ts`).
- **The bottom-left editor chips are INDEPENDENT panel toggles, not tabs** (reference parity, ADR-010): a floating bar (`absolute bottom-4 left-4`) of `Layers | Components | Properties` chips, each flipping its own panel's visibility — Layers (left w-60) and Components (a second w-60 column) can both be open; Properties toggles the right w-72 panel.
